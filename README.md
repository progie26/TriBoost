# TriBoost

三根手指静止放在触控板上，视频进入网站原生的长按倍速；手指抬起，立刻恢复。macOS 原生的三指拖移照常可用。

TriBoost 是一个菜单栏小工具。它被动读取触控板的原始多点触控数据，在识别到「三指静止」时发送一次右方向键按下，手指离开时发送松开——就是你手动按住方向键的效果，只是不用手去按。

## 支持的网站

只在 Google Chrome 位于前台，且当前标签页属于下列域名时启用：

| 网站 | 域名 | 长按右方向键的效果 |
|---|---|---|
| 哔哩哔哩 | `bilibili.com` | 3 倍速 |
| 爱奇艺 | `iqiyi.com` | 2 倍速 |
| 腾讯视频 | `v.qq.com` | 3 倍速 |

这三个是逐一实测确认的：驱动真实 Chrome 按住方向键，读取 `video.playbackRate` 的变化。

**没有收录的网站及原因：**

- **YouTube**——实测长按右方向键是**反复快进**（2.75 秒内前进 130 秒），`playbackRate` 始终为 1。它的长按 2 倍速走的是鼠标按住播放器，不是键盘。
- **优酷**——测试时遇到人机验证，未能完成验证，因此不收录。

读不到当前网址时，TriBoost 保持停用，不会在其他网页上误触发。

## 构建

需要 macOS 15 以上和 Xcode 16 以上（开发环境为 macOS 26.6 / Xcode 26.6 / Swift 6.3）。

```bash
git clone <仓库地址> && cd TriBoost
./Scripts/build-app.sh          # 产物：build/TriBoost.app
```

也可以直接用 Swift Package Manager：

```bash
swift build -c release          # 只编译可执行文件
swift test                      # 运行 47 个单元测试
```

## 安装

```bash
./Scripts/reinstall.sh      # 编译 + 装到 /Applications + 清理失效授权 + 启动
```

或者手动：

```bash
cp -R build/TriBoost.app /Applications/
open /Applications/TriBoost.app
```

建议放进 `/Applications`——「登录时启动」依赖 `SMAppService`，macOS 对不在标准位置的 app 可能拒绝注册。

### 从 Release 下载的话

Release 里的 `.app` 是 **ad-hoc 签名、未经 Apple 公证**的（开发者没有付费开发者账号）。首次打开时 macOS 会拦下来，提示无法验证开发者。解除方法：

```bash
xattr -dr com.apple.quarantine /Applications/TriBoost.app
open /Applications/TriBoost.app
```

或者在 Finder 里**右键 → 打开**，然后在弹窗里再点一次「打开」。

如果你更放心自己编译，直接用上面的 `./Scripts/build-app.sh`，源码全在仓库里。

## 授权

TriBoost 只需要**辅助功能**（Accessibility）一项权限，用途只有两个：

1. 读取 Chrome 当前标签页的网址，判断是否为支持的网站
2. 发送右方向键的按下与松开事件

首次启动会弹出说明并引导你打开：

> 系统设置 → 隐私与安全性 → 辅助功能 → 打开 TriBoost 的开关

授权后从菜单栏重新启用即可。

TriBoost **不联网**，不读取网页内容，不含统计、遥测、广告、账号、云同步或自动更新，也不会修改任何系统手势设置。

## 使用

菜单栏图标点开有五项：**当前状态**、**启用/停用**、**登录时启动**、**隐藏菜单栏图标**、**退出**。

当前状态会显示为：未启用、等待三指、倍速中、已识别为拖移、当前网站不支持、缺少辅助功能权限。

**手势：** 三根手指**轻放**在触控板上（不要按下去），保持静止约 0.2 秒，视频进入倍速；抬起任意手指，恢复正常速度。

如果三指在激活前就移动了，这次动作会被判定为系统的三指拖移，TriBoost 不发送任何按键。如果倍速已经开始后你才移动手指，倍速立刻结束，并且要等所有手指完全离开后才能再次触发。

### 隐藏菜单栏图标

选择「隐藏菜单栏图标」后，TriBoost 会继续在后台工作，三指倍速照常可用，只是菜单栏上看不到它。

**怎么再拿回控制：** 用 Spotlight（⌘ 空格）搜索 `TriBoost` 回车。再次启动一个已在运行的 TriBoost 不会开第二份进程，而是让图标立刻回到菜单栏并自动展开菜单，此时可以再次隐藏或退出。

隐藏状态会被记住，重启后依然隐藏。

## 阈值调整

所有可调数值集中在 `Sources/TriBoostCore/Thresholds.swift`：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `holdToActivate` | 0.20 s | 三指静止多久后按下按键 |
| `minimumKeyHold` | 0.50 s | 按键至少保持多久 |
| `settleGrace` | 0.15 s | 手掌落下时允许手指数变化的窗口 |
| `armingFingerMove` | 0.030 | 激活前单指最大位移 |
| `armingCentroidMove` | 0.020 | 激活前三指中心最大位移 |
| `activeFingerMove` | 0.045 | 激活后单指最大位移 |

位移单位是触控板归一化坐标（两个方向都是 0~1）。在 16 cm 宽的触控板上，0.03 大约是 5 毫米。

**关于 `minimumKeyHold`：** 在这三个网站上，**短按**右方向键是快进（B 站 5 秒、爱奇艺 10 秒）。网站需要大约 300~400 毫秒才认定为长按。如果手指刚放上就抬起，按键持续时间过短会被当成短按，视频直接跳过一段。因此按键按下后至少保持 0.5 秒。把它设为 `0` 可以恢复「手指一离开就立刻松开」的行为。

## 故障排查

**菜单栏没有图标**——TriBoost 没有 Dock 图标，只在菜单栏。图标是三个圆点加双箭头。菜单栏太挤时 macOS 会隐藏图标，先关掉几个其他菜单栏项试试。

**状态一直显示「缺少辅助功能权限」，但开关明明是开的**——最常见的坑，而且开关看起来是开的会误导你。

没有 Apple 签名证书时 app 只能 ad-hoc 签名，而 ad-hoc 签名把授权绑定在**二进制的哈希**上。只要重新编译过，macOS 就认为这是一个陌生程序，但系统设置里还留着上一版的开关——**看着是开的，实际不授予任何权限**。

用这条命令重装，它会自动清掉失效记录：

```bash
./Scripts/reinstall.sh
```

然后在 系统设置 → 隐私与安全性 → 辅助功能 里，**先用「−」删掉已有的 TriBoost 条目**，再重新打开开关。app 每秒轮询一次权限状态，开关一拨就立即生效，不需要重启。

**状态一直显示「当前网站不支持」**——确认 Chrome 在最前台，且当前标签页确实是上表中的网站。TriBoost 只看**当前活动标签页**，后台标签页不算。

**三指放上去没反应**——手指要**轻放**，不要按下去；三根手指分开一点，不要并拢成一根；保持静止，轻微抖动没关系但不要滑动。

**视频跳过了一段而不是倍速**——按键保持时间不够。调大 `minimumKeyHold`。

**三指抬起时视频暂停了**——这是 macOS 三指拖移造成的，不是 TriBoost 发的按键。实测：三指静止约 300 毫秒后，手指的微小抖动足以让系统判定为拖移并合成一次鼠标按下，抬手时补上鼠标松开，两者相距 1 个像素，浏览器读成一次点击。TriBoost 会在倍速进行中拦掉这一对事件（见下方「关于事件拦截」）。如果仍然发生，说明拦截没生效——检查辅助功能权限是否完整。

**倍速卡住不恢复**——按一下真实的右方向键即可解除。TriBoost 在退出、休眠、锁屏、切换用户、Chrome 失去前台、收到终止信号时都会发送松开事件，但**进程被强制杀死（`kill -9`）或断电时无法保证**——那种情况下没有任何代码能运行。

**三指拖移失灵了**——TriBoost 只在倍速进行中拦截左键按下/松开（见「关于事件拦截」），其余时候不碰任何事件，也从不修改系统设置。如果拖移在平时就失灵，请检查系统设置 → 辅助功能 → 指针控制 → 触控板选项。

## 实现说明

- **状态机**（`Sources/TriBoostCore/GestureMachine.swift`）是纯函数式的：没有自己的时钟，没有 I/O，全部决策来自传入的输入，因此可以完整单测。四个状态：`idle`、`candidate`、`speeding`、`cancelledForDrag`。
- **触控数据**通过 [`OpenMultitouchSupport`](https://github.com/Kyome22/OpenMultitouchSupport)（MIT）被动读取，实测采样率约 125 Hz。触控数据这一路是纯观察的，不会吞掉或改写任何触控板手势。
- **网址读取**走 Accessibility API 的 `AXURL`，不使用 AppleScript，因此不需要「自动化」权限，视频全屏时同样可读。注意：旧教程里的 `AXManualAccessibility` 在当前 Chrome 上已失效（返回 `kAXErrorAttributeUnsupported`），但不影响——网址在原生窗口树上，不在网页内容树上。
- **按键发送**用 `CGEvent`。实测这三个网站都只需要一次 keydown（它们用定时器判定长按），不需要自动重复事件；`KeyGuard.emitAutorepeat` 保留了发送自动重复的能力作为后备。
- **App Sandbox 必须关闭**，这是 `OpenMultitouchSupport` 的要求。

### 关于事件拦截

TriBoost 有一处**不是**纯被动的：`DragClickSuppressor`。

实测发现，三指静止约 300 毫秒后 macOS 会自行启动三指拖移并合成鼠标按下，抬手后补上鼠标松开——位移只有 1 个像素，浏览器读成一次点击，视频被暂停。这是本工具与系统三指拖移唯一真正冲突的地方，被动观察无法解决。

因此 TriBoost 安装了一个事件拦截器，**仅在倍速真正进行中**丢弃这一对左键按下/松开事件。其余任何时刻——没有倍速、不在白名单网站、Chrome 不在前台、程序停用——事件完全不受影响，三指拖移照常工作。判定逻辑在 `Sources/TriBoostCore/ClickSuppressionPolicy.swift`，有独立单测覆盖。

这是对「完全不拦截系统事件」这一初始约束的有意偏离，为的是让手势真正可用。如果你更希望保留纯被动、接受抬手暂停，删掉 `AppDelegate` 中 `suppressor.start()` 一行即可。

已知取舍：`OpenMultitouchSupport` 的核心以预编译 xcframework 形式分发，不是从源码构建。若要求全链路源码可审计，需要把它的 Objective-C 源码 vendor 进本仓库自行编译。
